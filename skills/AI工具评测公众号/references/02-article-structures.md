# 02 · 文章结构与五大实战模板（2.0 高密度版）

> 🔴 **2026-11-13 袁总定调（评测写作四大原则与叙事主线）**：
> 1. **四大写作黄金原则**：① **必有一手评测心得细节**（真实体感与微观场景切片，不写空泛概括）；② **评测必须带对比**（拉上竞品/前代/当前主力模型作参照）；③ **具体且言之有物**（落到真实数字、配置原件与第一人称活人感，不写冷冰冰说明书）；④ **强可视化**（本机实拍动图 GIF 与截图优先堆上，缺图去网上尤其是 **Twitter / X** 及第三方基准找真实截图）。
> 2. **彻底不写「踩了什么坑」**：关于“踩了什么坑 / 报错翻车 / 避坑实录”一律不写，统一按 **刚开始直接释放结果 → 过程中结合对比与一手细节讲清用法（配可复制原件） → 最后稍微延伸讲一下底层原理和人文思考** 推进。
>    - ⚠️ **2026-11-18 v1.6.0 澄清（这条不许再被误读）**：上一条「不写踩坑」约束的是**评测文的叙事结构**——不许把评测文写成翻车日记、不许用讲故事的口吻倒苦水。**实操分享形态（模板 4 / 5）必须给失败边界**，但要用「**症状 → 原因 → 一步补救**」三列表或边界清单的形态给，不是用叙事口吻讲过程。两条规则不打架：**评测文不写我的翻车过程；实操文必须写读者会撞上哪堵墙。**细则见 `references/08-practical-sharing-and-evidence.md` 第五节。
> 3. **快节奏 · 情绪张力 · 多图少字 · 信息增量（手机端公域推荐标尺）**：
>    - **多图少字（字数服从信息密度，不卡死）**：字数按信息增量自然浮动（通常 1000–2200 字，干货多可写到 2000 字左右，绝不凑字数也不硬砍干货），配 **8–12 张** 高信息量真图/GIF（约每 120–180 字见一图），图里已经展示清楚的字正文绝不重复复述；
>    - **快节奏 + 情绪张力**：砍掉所有背景科普铺垫，用真实第一人称情绪反转句（有期待、有怀疑、有打脸、有明确站队）推着读者往下滑；
>    - **信息增量**：每一段必须交付 1 个新事实、新数据、X 大V一手实测或可抄配置原件。
> 4. **彻底废除「按句号切开、一句一段」**：段落统一按 **2–3 行自然短段（40–60 字，校验上限 ≤80 字）** 切分，严禁出现连续 3 段 ≤15 字的电报碎句。
> 5. **清爽视觉铁律（零图注 + 禁「原件一二三」拥挤框）**：配图下方**一律不加灰色小字图注**；凡是高清配图/信息卡已经展示清楚的内容，**严禁在下方再塞 `【原件 1/2/3】`、`【速查卡】` 等拥挤的重复文字框**！需要给读者复制的终端命令只留 1–4 行纯命令，搭配 1 张清爽的 Markdown 对比表即可。
> 6. **开篇三件套去重硬闸**：骨架自带的「开篇卡金句」→「目录/看点」→「第一章标题」→「正文首段」，四者语义必须层层递进，严禁把同一句话车轱辘说三遍。

## 一、四个一票否决项（触犯任意一条直接打回重写）

1. **无独家发现**：把文章里的模型/工具名字挡住，整篇话依然成立（全是正确的行业废话）。
2. **开篇慢热无结果**：前 2 段还在背诵“随着 AI 大模型飞速发展”，没有第一时间把跑通后的惊艳结果摆上桌。
3. **结尾和稀泥**：横评结尾写“各有千秋，大家按需选择”，不敢明确给出「谁现在立刻用哪款」的清晰选型结论。
4. **无原件可拿走**：通篇只顾着自己嗨聊感受，读者读完连一条完整的测试 Prompt、配置命令或用法速查表都复制不走。

## 二、五大结构模板（三套评测 + 两套实操）

### 2.0 先判形态（选模板的前置闸）

v1.6.0 新增判据，写提纲前必须先过这一关。判据三问（细则与映射表见 `references/08-practical-sharing-and-evidence.md` 第一节）：

| 三问 | 都答「是」→ 评测骨架（模板 1–3） | 出现「要做出东西」→ 实操分享（模板 4 / 5） |
| :--- | :--- | :--- |
| 读者要的是「买不买 / 换不换 / 选哪个」吗？ | 是 | 否 |
| 核心证据是「同题对比 / 胜负总表」吗？ | 是 | 否（核心证据是**我做出来的那个交付物**） |
| 读者能照着复现出一件东西吗？ | 不必须 | 必须 |

**判错体裁的代价**：标题许的是做出东西、正文却是背景科普，读者拿不走步骤；标题许的是结论、正文却是从零安装，读者拿不到站队。体裁判定结果要写进选题卡，骨架跟着形态走。

---

### 2.1 模板 1：【单品深度实测 / 首发快刀斩】
- **匹配骨架**：`ticket`（汇芯红·票据封面）
- **推荐字数**：1500–2200 字｜**真图数量**：6–10 张（含 ≥1 张动图 GIF 或核心界面实拍）
- **推进结构**：
  1. **票据封面卡**：亮出工具名、实测星级、S/A/B/C 等级与一句话结果结论。
  2. **01 开篇释放结果**：用具体业务场景开场（1–2 段内必见首张成品大图或 GIF），直接展示用上它之后省了多少力、拿到什么惊艳结果。
  3. **02 核心功能与方法拆解（原件块 ①）**：手把手讲清楚最核心的 2–3 个实用功能怎么用，用代码块或表格完整贴出**执行命令 / Prompt 原文 / 目录规范**，让读者能照着立刻复现。
  4. **03 3 分钟领用与配置指南（原件块 ②）**：给出零门槛安装或上手步骤 + 可直接复制的《安装与日常使用指令卡》。
  5. **04 底层原理与人文延伸**：用通俗类比讲透它为什么好用的底层原理（如母语意图层 vs 机器契约层），再结合一人公司实战稍微延伸一点人文思考（工具越多越要给大脑做减法），温暖有力地收尾。

---

### 2.2 模板 2：【多模型 / 多工具同题横评】
- **匹配骨架**：`magazine-card`（汇芯红·杂志快讯封面 + 横向滑动目录）
- **推荐字数**：2000–3000 字｜**真图数量**：8–12 张（每轮对比必有同框或连续实拍图）
- **推进结构**：
  1. **杂志快讯开篇卡**：划掉一句旧认知，用红黑大字亮出本次横评的最大结论。
  2. **01 省流结果总表先行（第一屏直接给答案）**：开篇 2 段内直接上 **《横评结果与路由总表》**（维度：速度 / 质量 / 成本 / 最佳适用场景），第一时间释放结论。
  3. **02 实测方法与标准考卷（原件块 ①）**：交代测试环境，贴出本次横评统一使用的 **标准测试 Prompt / 任务单代码块**，告诉读者怎么测、怎么用。
  4. **03 逐轮实操展示与组合拳方案（原件块 ②）**：展示各工具的高光产出截图与效率数据，给出《不同预算/角色的最优组合配置单》。
  5. **04 底层原理与人文延伸**：从模型架构或产品哲学角度点透差异背后的原理，并延伸到创作者与一人公司如何驾驭工具矩阵的人文思考。

---

### 2.3 模板 3：【Agent Skill / MCP / 新功能深扒】
- **匹配骨架**：`classic-edit`（汇芯红·经典编辑引言卡 + 三列看点 + 编号章节）或 `ticket` / `journal`
- **推荐字数**：1500–2200 字｜**真图数量**：6–10 张
- **推进结构**：
  1. **引言卡 + 看点短标**：点明这个 Skill 替你拿到了什么结果。
  2. **01 先看跑通后的交付结果**：第一屏直接晒出用该 Skill 跑出来的最终成品截图/录屏，并给出开源/领用链接。
  3. **02 核心巧思与实操方法（原件块 ①）**：讲清楚它最懂业务的设计巧思与使用流程，贴出《功能对照表 / 目录速查表》。
  4. **03 3 分钟极速安装与上手（原件块 ②）**：贴出可直接复制的 **安装配置命令 / 调用口令卡**，让读者三分钟搬回家。
  5. **04 底层原理与人文延伸**：稍微延伸讲一下背后的工作流原理与一人公司减法哲学，升华收口。

### 2.4 模板 4：【实操分享 · 从零做出一件东西】（v1.6.0 新增：装 / 跑 / 出片 / 上线）

- **匹配骨架**：`classic-edit`（编号章节 + STEP 卡 + 深色代码块，最贴步骤文）；单点复刻或一次翻车修好可用 `ticket`
- **推荐字数**：1200–2500 字（步骤多寡决定，绝不注水）｜**真图数量**：8–14 张（每个关键步骤至少 1 张，成品至少 1 张）
- **适用判据**：读者拿到文章是要**做出一件东西**，而不是要做决定。
- **推进结构**：
  1. **首屏先给交付物（成果先行，不许铺垫）**：第一屏直接放「做出来的那个东西」——成品图、成片静帧、上线地址、跑通的目录树，任选其一。**紧接着一行交代它是怎么来的**：谁做的、什么条件、花了多少时间。**交付物必须可核**：图里能看见时间、文件名、尺寸、状态之一。设计稿、示意图、概念图不算成品，只能放在「我计划长这样」。
  2. **版本锚点行 + 范围声明（放在正文前 1/3）**：
     - 一行锚点：**工具及版本 / 模型名 / 硬件或云卡 / 额度或积分 / 操作日期**，五字段缺一不可；不许用「限时免费」这类活动名当锚点。
     - 一句范围：覆盖到哪一步（能装能跑 / 能出片 / 能上线）、不覆盖什么、手册型写清「只到第几个」。
  3. **最短成功路径（第一章从读者的卡点开始）**：先给一条能跑通的最短路径，不讲原理、不讲名词。**第一章从读者最容易卡住的那个动作开始**——硬件不够的从显存讲起，环境装不上的从装环境讲起，而不是从「什么是节点」「什么是 AppID」讲起。把失败现场当目录用。
  4. **逐步加难 + 每步定稿物（原件块 ①）**：在最短路径跑通之后，再逐个加一层难度。每一步都必须写清**本步定稿物**：产物文件名与形态（例如 `narration.md`、`final.wav`、`captions.srt`、`timing.json`、`final.mp4` 这类）。读者据此能判断自己走到哪、下一步缺什么。可复制内容（提示词 / 命令 / 参数组）必须四件齐：**原话 / 上下文 / 换来的结果 / 失败边界**，缺一件就标缺口。
  5. **失败边界表（原件块 ②，必写，不许省）**：三列表——**症状（屏幕上那行字）→ 原因 → 一步补救**。缺列不算写完。禁止「注意版权」「注意安全」这类空警示，禁止只写情绪。一次真实翻车可写成时间对：第一次跑出的结果 → 修好之后的结果，中间夹一句「改了什么」。
  6. **边界与不适用场景 + 收口**：明确写什么条件下这套方法不成立、哪些场景不该用。最后一句最小可执行动作，让读者现在就能开始第一步。
- **正例（结构参照）**：
  - 「一关一关交钥匙」的进度结构：每章结尾固定一句「这时候，你手上有：……」，读者随时知道自己走到哪。
  - 硬件分档当判断轴：先讲显存够不够、把人分流到不同方案，再讲安装。
  - 产物文件名清单：把「一环扣一环」变成可检查的文件序列。
- **反例**：
  - 交付物在第四屏才出现；开头先讲「今天教大家……」「随着 AI 发展……」。
  - 用设计稿 / 示意图冒充成品放在首屏。
  - 只贴提示词不贴回显，正文写「效果非常好」。
  - 只说「交给它跑，它会自己完成」，读者不知道自己手上该有什么文件。

### 2.5 模板 5：【手册 / 词典型（参数 / 词条 / 模式表）】（v1.6.0 新增）

- **匹配骨架**：`journal`（对照表承载信息），封面可配 `paper`；条目少而短可用 `minimal-line`
- **推荐字数**：1500–3000 字（条目数 × 单条篇幅决定）｜**真图数量**：4–10 张（表单类界面、参数页、对照示意见图即可，不硬凑 8 张）
- **适用判据**：材料主体是「名称 + 做什么 + 怎么用」的平铺条目，读者要的是**查得到、对得上**，不是胜负排名。
- **推进结构**：
  1. **范围声明前置（第一条，不许挪到文末）**：本篇写几个、写到第几个为止、不覆盖什么。手册型必须写明「本篇只到第 N 个，下篇从第 N+1 个继续」。**范围声明是可信度，不是免责套话。**
  2. **一句话结论体系**：先把整张表的判断逻辑讲清楚——这些条目之间是什么关系、按什么维度分、读者该怎么用这张表。一到两段，不展开科普。
  3. **逐条五件套（主体区）**：每个条目固定五个字段——**中文名 + 英文名/别名 + 常见变体 + 适用位置 + 一句可直接交付的描述**。字段顺序全篇统一，不许中途换格式。
  4. **易混对照表（原件块 ①）**：把读者最容易搞混的两三个条目单列一张对照表，一行一个差别，直接说在什么情况下选哪个。
  5. **反例区（原件块 ②）**：给出错误写法/错误配置的样例，并说明错在哪里、会看到什么现象。这一节是手册型可信度的来源。
  6. **收口**：一句最小可执行动作（例如「先只用第 1 条，跑通再回来查第 4 条」）。
- **正例（结构参照）**：
  - 词条五件套 + 开头声明「本篇只到第 N 个」。
  - 用对照表承载信息，正文不复述表里已有的字。
- **反例**：
  - 手册型硬套「五幕评测」外壳——读者期待胜负，拿到的是词表。
  - 条目格式前后不一致（前三条五个字段、后面变成两个）。
  - 标题写「最全 / 完整版」，却没写范围声明、也没有收录清单。

## 三、标题实验室 2.0（每次出 6 个实质差异候选，严禁喊麦）

1. **三要素硬公式**：**「具体数字/成本 + 反差/冲突结果 + 读者可拿走物/高权流量词」**。
2. **字数控制**：14–22 个汉字为最佳视觉甜区；涉 `WorkBuddy`、`Claude`、`DeepSeek`、`Cursor` 等高权词必须保留在标题前半段。
3. **量词必须被正文兑现**：标题里的「万字」「最全」「完整版」「一篇就够」都要有对应体量与覆盖度。兑现不了就改标题，不许靠加长铺垫凑数。
4. **绝对禁区**：
   - 禁喊麦夸张词：震惊、炸裂、封神、天花板、遥遥领先、吊打、最屌、唯一、100%。
   - 禁中庸解释尾：严禁在有张力的标题后面接「但人还得盯着」「各有优劣」这类卸力废话。
   - 禁说明书裸标题：严禁「XX 模型 2.0 深度评测」「XX 工具使用指南」。
5. **高命中示范**：
   - *花钱实测型*：`花 280 元连测 4 款编程 AI，我把最火的那个退订了`
   - *同题反差型*：`同一份 50 页合同丢给 3 个大模型，免费的赢了 199 的`
   - *Skill 生产力型*：`把这个飞书 Skill 塞进工作流后，我砍掉了每天 2 小时的周报`
   - *实操交付型*：`12GB 显存跑通，一套流程出 3 条竖屏成片`

## 五、反僵化灵动结构规范（严禁千篇一律套八股）

1. **按赛道动态切骨架（禁止每篇硬套「第一回合/第二回合」或五幕）**：
   - **基座模型 / 性价比之战**：走「打假算账 → 实操压测 → 会员额度体感 → 路由分流表」。
   - **视频 / 图像生成工具**：不谈 Token 单价和 JSON 配置，直接走「3 秒炸裂成片 GIF 开场 → 连抽 5 次废片率实录 → 物理/手部崩坏抓拍 → 单条成片真实成本」。
   - **AI 编程 / IDE / Skill**：围绕 1 个真实多文件项目现场推进——「需求提出 → 改坏报错现场 → 自愈或人工兜底 → 实省时间账」。
   - **单点实验 / 趣味脑洞**：整篇只讲 **1 个完整故事**，小标题直接使用当下心理台词（如「我以为要翻车了」「结果它干了一件离谱的事」），自然起承转合。
   - **实操分享（v1.6.0）**：走「首屏交付物 → 版本锚点 + 范围声明 → 最短成功路径 → 逐步加难 + 每步定稿物 → 失败边界表 → 不适用场景」。
2. **开头由「最意外的实测瞬间」决定**：先真跑桌面、刷 X 线索，再写提纲；今天最让人皱眉或惊艳的那 1 秒在哪里，文章第一句就从哪里切入。
3. **六套视觉外壳轮换**：根据内容气质在 `magazine-card`、`ticket`、`classic-edit`、`journal`、`minimal-line`、`zen-space` 之间轮换，避免连续多篇使用同一套外壳导致读者审美疲劳。带步骤的实操文优先 `classic-edit`，手册文优先 `journal`，不要为了「换外观」牺牲读者找步骤的效率。
