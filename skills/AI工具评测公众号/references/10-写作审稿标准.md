# 写作与审稿标准
## 成稿路线按发现选择
- 单品：读者问题 → 有条件的结论 → 关键任务及产物细节 → 影响使用的限制 → 行动建议。
- 横评：谁在什么任务下更合适 → 同题结果与条件 → 造成差异的具体因素 → 按需求推荐。只在维度可比时使用结论表。
- 选购分析：用户已有工具和需求 → 已核实套餐/限制 → 增量价值与机会成本 → 哪种情况值得付钱。缺体验就不评实际质量。
- 教程：结果预览 → 前提与材料 → 连贯步骤 → 结果检查 → 常见卡点。关键步骤必须真实核验。
这些是可选路线，不是每篇的必填栏目。

## 有价值的细节
少写「强大、高效、普通人必备、降维打击」。优先解释：输入包含什么难点；产物哪里正确、哪里错；需要怎样修改；改完是否能交付；谁会被这个问题影响。
例句仅用于示范表达，不是真实案例，不得直接充当自测证据：
差：「它生成PPT很强，但有时不稳定。」
好：「这一轮标题层级清楚，但材料里的两组年份被合并了。用于对外汇报前，需要对照原文检查数据。」
没有该轮真实记录时，后一句也不能使用。
不把谨慎写成免责声明墙：将范围放在相关结论附近即可。资料与实测可混合使用，但归因要清楚。

## 否决项：任一存在则不得标记可发表
虚构体验/数字/截图/人物故事；把官宣或第三方结果冒充亲测；标题或核心结论超出证据；核心动态事实未核验；关键比较条件缺失；隐私泄露；用户身份或商业成果被夸大；来源无法支持主张；成稿出现法官腔/翻案腔/提示冒号包装（见 `18`/`06` §1b）。缺证据时删改、补证或变更类型，不靠润色通过。

## 内容质量逐项检查
1. 一句话能说清读者问题与最终建议吗？
2. 有至少一个与决策有关、超出官网复述的判断吗？
3. 每个核心判断有可指向的证据，事实与推断分开了吗？
4. 有没有能改变读者选择的具体细节与限制？
5. 将工具名替换成任意竞品，是否仍然成立？成立的段落通常太空泛，需改写。
6. 开头是否尽快给到真实问题和信息，而不是铺情绪？
7. 同一观点是否反复说？每节是否提供新信息？
8. 图片是否证明了正文判断？正文与产物是否一致？
9. 标题承诺是否逐一兑现？不靠悬念掩盖无内容。
10. 行动建议是否有门槛、适用条件和低成本验证办法？
每项写「通过/待修/不适用」及对应段落或理由。不使用机械总分掩盖短板，不保证阅读量。待修项处理后再交付；若受阻则明确交付为草案。

## 改稿
先诊断问题属于选题、证据、判断、结构还是语言；优先修前四项。保留有价值的原始观察，不把长文压成口号。给修订稿及3条以内关键修改说明；没有原文时不得宣称已诊断某篇成稿。
