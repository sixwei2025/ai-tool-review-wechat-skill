# 05 · 活人感写作技法与人机边界（融合吸收卡兹克 `khazix-writer`）

> 致谢与来源说明：本节部分写作技法（HKR 质检、人机边界、升番逻辑、契诃夫之枪、AI 高危暴露词）借鉴自数字生命卡兹克（Khazix）开源项目 [`KKKKhazix/khazix-skills`](https://github.com/KKKKhazix/khazix-skills) 中的 `khazix-writer`，并按 **袁六伟 · 台州汇芯** 的商业实战人设与「自然短段 / 零踩坑 / 汇芯红骨架」规范做了本地化融合改造。

---

## 一、选题 HKR 质检（动笔前先过三关）

任何评测选题开写前，先自检是否至少满足以下两项（三项全中为 S 级爆款潜质）：
- **H（Happy / 悬念）**：标题和开头有没有让人好奇想点开的反差或实测结果？
- **K（Knowledge / 信息量）**：读完能不能拿到具体数据、官网真价或可抄走的配置原件？
- **R（Resonance / 共鸣）**：能不能戳中一人公司或创作者的真实业务痛点？

## 二、人机协作边界（什么交给 AI，什么必须真人给）

| 归属 | 明确分工 |
| :--- | :--- |
| **AI 负责** | 找历史/行业佐证、把技术参数翻译成 10 秒听懂的生活类比、梳理章节结构、按定好角度扩写、按校验脚本自检 |
| **真人必须提供（严禁 AI 编造）** | 一手实测体感与反直觉发现、真实业务账单与运行结果、体感情绪词（用「我专门去核了两遍官网」代替「我很震撼」） |

> **实操分享形态补充一行（v1.6.0）**：AI 可以帮你把提示词结构化，但**上下文必须来自你真跑过的那一次**。谁的硬件、哪个版本、哪个额度档、什么输入，这些 AI 编不出来，编出来就是伪造实测。

## 二·补、引用与借鉴的三条线（v1.6.0 新增，可学 / 可短引 / 不可搬）

原创归纳的前提是分清「学什么」和「搬什么」。三条线，越往后越不能碰：

| 线 | 允许什么 | 边界与操作要求 |
| :--- | :--- | :--- |
| **1. 可学** | 结构、判据、顺序、边界表、决策树、信息组织方式 | 学完必须用**自己跑的数据与自己的场景**重写内容。学结构不丢人，丢人的是学完还写着别人的事 |
| **2. 可短引** | 不超过**必要一句**的原话 | 必须带来源 url，必须有自己的解读。一句能说清就不用两句；引完不解读等于搬运 |
| **3. 不可搬** | 整段原文、提示词全文、别人的口吻与招牌句式 | **同义词改写也算搬**。换个说法不产生原创，只产生洗稿 |

三条补充：

1. **二手材料只能当方法样本**。解读别人公开的方法，句式落在「他公开的方法是……」「这套思路可以这样迁移到……」，不得写成「我试了，确实……」。对方的效果数字不是你测的结果。
2. **引用他人的成绩数字必须带口径**。是官方公布、是粉丝数、还是本帖曝光？口径缺失就只能当「作者称」处理，不得当作自己的结论背书。
3. **原文链接未取得就写明**。没打开就写「原文链接未取得」，不许装成读过了。

## 三、四大高阶活人感写法（让评测从说明书变成好文章）

1. **「升番逻辑」逐轮推进**：
   - 展示模型或工具能力时，不要一上来把所有结论平铺完，而是按 **基础任务（还行）→ 进阶业务（有点意思）→ 真实复杂工作流一次跑通（惊艳）** 的情绪曲线递进，推着读者往下看。
2. **「契诃夫之枪」回环呼应**：
   - 开头抛出的核心疑问或小钩子（例如“网传价格只有 1/10 是真的吗？”），必须在后文核价表和最终结论里响起来，形成前后因果闭合的作品感。
3. **「聊天式知识输出」与口语转场**：
   - 遇到技术词不要写“下面我来给大家科普一下”，而是像跟朋友聊天一样顺手掏出类比；多用「说实话」「坦白讲」「有意思的是」「这下就对上了」做自然转场，避免使用粗俗脏话。
4. **理解对立面的处境**：
   - 给选型建议时，先站在对方真实工作场景里（“如果你每天不需要重度折腾终端运维，核心诉求就是写长文和跑视频脚本”），再给出明确推荐，说服力翻倍。

## 三·补、实操文里的失败怎么写才不变成踩坑流水账（v1.6.0 新增）

先厘清一个容易打架的地方：`references/02` 说「彻底不写踩了什么坑」，`references/08` 说「实操分享必须给失败边界」。两条都对，管的是两件事。

- **评测文不写我的翻车过程**：评测文的主体是结论与对比，翻车故事会稀释判断。失败以边界清单、一句「这一档配置只能跑得动」的形式出现，不占用叙事篇幅。
- **实操文必须写读者会撞上哪堵墙**：读者照着做，一定会遇到报错。不写，教程就是半成品。

实操文的失败必须写成**三列表**：症状（屏幕上看到的那行字/那个现象）→ 原因 → 一步补救。四个具体禁令：

1. **禁止空警示**：「注意版权」「注意安全」「小心封号」没有症状、没有原因、没有动作，不算失败边界。
2. **禁止情绪表演**：「我差点崩溃」「折腾了一整天」不交代症状和补救，属于无效篇幅。
3. **禁止转述症状**：症状要能让人对号入座，照抄报错原文或现象原样，别概括成「报了个错」。
4. **禁止一个症状配三个并列方案**：给一个主要补救动作，读者要的是下一步，不是选项菜单。

推荐写法：**时间对**。第一次跑出的结果 → 修好之后的结果，中间夹一句「改了什么」。读者拿的是因果，不是剧情。

## 四、AI 高危暴露词补充清单（已接入 `validate_review_article.py`）

除大厂黑话、法官腔与极限词外，正文中严禁出现以下高频“AI 暴露词”：
- **禁用词**：`说白了`、`意味着什么`、`这意味着`、`本质上`、`换句话说`、`不可否认`。
- **替换思路**：直接删掉连接词，把后面的大白话判断直接说出来。

## 五、汇芯评测号「四合一独树一帜文风规范」（hao2 专属）

1. **情绪现场切入，不做冷冰冰报告**：开头从具体生活/刷屏现场切入，先打假或提出反常识疑问，再用真实账单或第一手截图立住结论。
2. **四回合递进横评，厚实有肉（2000–3000 字）**：重磅模型或核心工具评测按「**算账与极速横评 → 同题实测+可抄 Prompt → 本地真实工作流调度 → 极限翻车边界与分流表**」展开，保证信息增量饱满、读完不觉单薄。
3. **会员额度与时间账双算**：不仅算 API 每百万 Token 单价，更要写清普通人最关心的**会员额度真实损耗**（如 $20 Pro 会员 / $100 高配额度连写多篇掉百分之几）和**时间压缩收益**（如 40 分钟压到 4 分钟）。
4. **图前必有导读句**：严禁两张以上图片连续堆放无文字过渡；每张图/GIF 前必须有 1 句指路提示，告诉读者看哪里。
5. **科技与人文温度收尾**：结尾不喊空洞口号，落回“**算力普惠让昂贵工具变成普通人手边的一盏灯**”这一层人文与创业者温度。
6. **实操分享形态不必强凑四回合（v1.6.0）**：模板 4 / 5 的长度服从步骤与条目数量，不为了「厚实有肉」注水。但「图前必有导读句」「失败边界成表」「收口给出一个最小可执行动作」这三条在实操文里同样强制。

## 六、反机械化写作四条硬铁律（2026-11-18 实战沉淀）

1. **禁止匀速复句填空**：严禁连续 4 段以上都用 50 字左右的“A，B，C。”匀速长复句。每 3～5 段必须穿插 1～2 个极短句或反问句（如「大错特错。」「听完我就笑了。」「为什么会这样？」）制造真人呼吸节奏。
2. **禁止导游式引图报幕**：严禁写「下面这张图展示了… / 为了方便大家看清，我把…放在下面」。必须先讲完人的动作、体感或判断，再让截图作为证据自然长出来。
3. **禁止重复背履历与斜杠清单**：开篇或担保位提过一次核心背书后，正文严禁反复背诵；章节导读禁贴满屏 `·` 和 `/` 的数据库式条目，改用大白话口语顺着讲。
4. **带引号的原话现场优先**：写痛点或案例时，优先放出具体人物带引号的原话和具体动作（几点几分、发了什么语音、截图里看到什么），禁用「很多人觉得 / 不少朋友遇到」的抽象概括。
