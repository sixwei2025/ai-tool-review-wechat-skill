# 03 · 视觉配图、实操截图卡与动图（GIF）规范

> 🔴 **2026-11 视觉第一铁律**：
> **真实实测截图 / 真实录屏 GIF ＞ 官方数据原图 ＞ 结构化数据卡**。
> **全面禁用 AI 插画与小黑图**：评测号读者只信真凭实据，绝不用 AI 生成的科幻插画或概念图凑数。
> 🔴 **2026-11-18 v1.6.0 增补**：图不是装饰，是证据。**每一句「效果很好」都要有一张能对上的图**；没取得的图不许假装有（见第一节第 5 条与第二节第 8 条）。

## 一、素材从哪里来？（四大正规水源）

### 1. 本机一手真跑截图（占全篇配图 70%+，每篇 8–12 张）
- **终端 / CLI 实测**：命令执行过程、耗时统计、Token 消耗回执、成功/报错日志。
- **IDE / 桌面端 / 网页工作台实测**：同题输入与输出界面、生成结果预览、多窗口并排对照。
- **性能与账单后台**：OpenRouter / 百炼 / 官方 API Billing 扣费明细、首字延迟（TTFT）与吞吐量实测面板。

### 2. 高信息量动图 GIF（每篇 1–3 处，首屏钩子后必放 1 张）
评测文章有动图，说服力翻倍。动图从以下 3 种方式获取：
- **流式生成速度 PK 录屏**：用无头浏览器（Playwright / Chrome）或屏幕录制，把两个模型同时吐字/跑代码的过程录成 3–6 秒短视频，转成 GIF。
- **多步操作连拍合成**：把连续 3–5 张关键步骤截图用 `ffmpeg` 合成为带停留节奏的轮播 GIF。
- **多模态成片切片**：测视频/动画模型时，直接用 `ffmpeg` 截取最具代表性的 3 秒高光或翻车片段转成 GIF：
  ```bash
  # 标准高清小体积 GIF 转换命令（调色板优化，控制在 3MB 以内适配微信）
  ffmpeg -y -i input.mp4 -vf "fps=12,scale=640:-1:flags=lanczos,split[s0][s1];[s0]palettegen=max_colors=128[p];[s1][p]paletteuse=dither=bayer" output.gif
  ```

### 3. 官方一手技术报告、X（Twitter）热帖与第三方榜单（占 20%）
- **X（Twitter）原帖与大V实测截图 / Demo 转 GIF**（详见 `references/06-twitter-x-sourcing.md`）：截取官方发布 Thread、一线开发者实测原帖卡片，或将 X 上的 Demo 视频切为 3–5 秒高清 GIF，正文中明确标注 `@handle` 来源。
- 官方 Technical Report / Blog 中的架构拆解图、官方定价套餐页截图（必须裁掉无关导航栏，保留价格与限制小字）。
- 权威独立基准：LMSYS Chatbot Arena 盲测榜、Artificial Analysis（速度 vs 价格散点图）、Vals Index 真实得分表。

### 4. 结构化数据卡与横评表（占 15%，无界面可截时补位）
- 当展示多维评分、成本算账公式、选型路由时，优先使用当前汇芯红骨架内置的 **斑马纹表格 / 两列或三列数据卡 / 对比摘要卡**。
- 若需独立可视化图表（折线/柱状/气泡对比），渲染为白底 + 汇芯红 `#C8102E` + 深炭黑 `#1C1917` 的干净图表，并在图说注明「实测数据整理」。

### 5. 未取得的资产怎么写（v1.6.0 新增）

有些素材拿不到，这很正常；**拿不到却装作有，才是事故**。三类未取得资产按下列固定口径处理：

| 未取得的资产 | 正文固定写法 | 硬规则 |
| :--- | :--- | :--- |
| **视频（成片 / 录屏 / Demo）** | 「成片效果在视频里，**视频效果未验证**。」 | 没看视频，正文**不得出现任何对其画面的描述**：不能写「口型很准」「运镜丝滑」「衔接自然」「动作稳定」。**静帧不能代替视频**：静帧不含时序信息，看一张图推不出「衔接自然」，由静帧得出的结论必须降级为「截帧显示……」。 |
| **资料包 / 课件 / 开箱库 / 源码包** | 「该资产在未取得的包内，本篇不展开。」 | **未取得 ≠ 已读**。包内步骤不得写成已完成步骤，包内参数不得写成自己核过的参数。必须提到时只写「据作者描述，包内包含……」，并明确标注是转述。 |
| **他人视频与他人成片** | 「证据在这段视频里，本篇未逐帧核验。」 | 引用他人成片只能写到「有这段视频」为止，不得替对方描述画面细节。 |

**设计稿 ≠ 成品**：设计稿、示意图、界面概念图不得放在「成果先展示」位置，只能放在「我计划长这样」。第一屏的交付物必须是可核的成品——图里能看见时间、文件名、尺寸、状态之一。

## 二、实操截图卡「八要素」标准（严禁裸截图直接进正文）

任何本机截图进正文前，必须满足以下处理标准（可调用 `make_shot_card.js` 或 Pillow 脚本加工）：

1. **先裁噪音**：裁掉浏览器多余标签页、书签栏、半截无关卡片、左侧无关历史会话列表。
2. **隐私红线打码**：API Key、手机号、邮箱、服务器真实 IP、未公开客户名、左侧其他私有星球/项目名必须彻底裁掉或高斯模糊遮挡。
3. **统一汇芯红描边与高亮框**：用 `#C8102E` 红框精准框出读者最该看的那一行数字、报错或结论（一张图最多 1–2 个框，不遮挡原文）。
4. **序号/结论角标**：多步操作或 A/B 对比时，在左上角或高亮处加清晰的序号标签（① / ② 或 `Claude` vs `GPT`）。
5. **手机 375px 可读性硬闸**：超长页面必须拆取局部核心区，严禁把整张 4K 大屏缩成手机上完全看不清字的细条。
6. **有输入必有输出**：只有 Prompt 输入框没有模型返回结果的截图，不算有效证据。
7. **逐张肉眼核验**：脚本生成或转换后，必须实际查看图片像素，确认无破图、无黑边、框线未偏位。
8. **宣称—图证对照（v1.6.0 新增，八要素的最后一条也是最难的一条）**：
   - 进正文前，先在作业稿里做一张两列表：左列「**我要宣称什么**」，右列「**哪张图 / 哪段日志 / 哪行数字能证**」（写文件名 + 位置即可）。
   - **右列为空** → 这句话要么删掉，要么改写成「作者称」「网传」。
   - **右列只有形容词**（「效果非常好」「明显更流畅」）→ 视为空，同样降级。
   - **右列与左列对不上**（正文写 10 秒，截图里是 5.167 秒）→ **不许替作者圆场，把差异原样标成疑点写出来**。差异本身就是信息。
   - 同一题里既有成功样本、也有失败样本，可信度远高于「四轮全成功、零失败」。失败现场原样贴出（接口返回空列表就是空列表，不配成功文案）。
   - 细则与正反例见 `references/08-practical-sharing-and-evidence.md` 第四节。

## 三、封面规范（六套高客单价杂志风主题 + 几何硬闸，严禁廉价培训班海报风）

> 🔴 **2026-11 封面铁律**：全面对接自动化公众号的 `wechat-cover-skill/scripts/render_cover_themes.py`（使用 `/opt/homebrew/bin/python3.11` 运行 Playwright + Chrome 渲染并过 DOM 几何硬闸），**彻底废除粗金描边字、大红贴纸徽章、杂乱网页底图与漂浮人头抠图**。

1. **执行器与六套主题选型（按内容结构直选）**：
   - `brand`（**汇芯红**）：通用主力，米白纸感底 + 汇芯红点睛，与正文汇芯红排版一脉相承
   - `indigo`（**靛蓝瓷**）：AI 模型/工具实测、技术拆解、产品更新
   - `swiss`（**瑞士蓝**）：多模型同题横评、榜单清单、纯数据对比
   - `midnight`（**午夜墨**）：带硬数字的结果复盘、算账对比、深夜深度长文
   - `paper`（**纸本墨**）：Agent Skill 教程、方法论、配置清单
   - `kraft`（**牛皮纸**）：一线实战复盘、工作流实录
2. **标准 `cover_brief.json` 结构与渲染命令**：
   ```json
   {
     "kicker": "AI 视频工厂 · 开源特辑",
     "brand": "Local Video Hub",
     "title_lines": ["一句话出片背后", "我的视频工厂"],
     "subtitle": "视频版 Obsidian · 全套代码与 Skill 开源",
     "meta": "NO.01 / 2026.11"
   }
   ```
   ```bash
   /opt/homebrew/bin/python3.11 skills/AI工具评测公众号/wechat-cover-skill/scripts/render_cover_themes.py \
     --brief cover_brief.json --themes brand --out ./assets/cover
   ```
3. **DOM 几何硬闸（不许绕过）**：
   - 脚本自动通过 Playwright 量取文字边界：标题、品牌行、副标题右边界不得越过 `1334px`（1:1 裁切安全线），不得压入右侧真人脸部区域；
   - 若报 `ERR ... 右边界 > 安全线 1334`，必须精简 `title_lines` 字数（每行建议 6–7 个汉字）后重跑，**严禁改脚本关闸**；
   - 渲染完成后，将 `cover-<theme>-wide.png` 缩放导出为 `900×383` 的 `cover_900x383.jpg` 上传。

## 四、配图引用与零图注铁律

1. **正文图片路径规范**：Markdown 内可写作 `![描述](01-claude-vs-gpt.png)` 或 `![描述](assets/01-claude-vs-gpt.png)`，推箱脚本会自动兼容两种路径并上传替换为微信 CDN URL。
2. **配图下方零灰色小字（2026-11-13 袁总拍板）**：高清配图和信息卡本身已经清晰展示内容，**图片下方一律不加任何灰色小字图注**（`markdown_to_wechat_article.py` 已全局关闭图注渲染并自动忽略图片后的括号说明行）。
3. **图前必有导读句（v1.6.0 提醒）**：零图注不等于零引导。除首屏钩子图外，每张图/GIF 前必须有 1 句指路提示，告诉读者看哪里；但这句提示放在图上方的正文里，不是图下的灰色小字。
