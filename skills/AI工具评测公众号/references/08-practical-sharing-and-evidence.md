# 08 · 实操分享形态与证据纪律

> 🔴 **2026-11-18 定版（v1.6.0 新增）**：
> 本文件只解决一个问题：**「我说我做出了什么，凭什么让人信」**。
> 它管的是「实操分享」这一类体裁——读者看完不是要**做决策**（买不买、换不换、选哪个），而是要**做出一件东西**（装出来、跑出来、出片、上线）。
> 写法总纲：**成果先展示 → 最短成功路径 → 逐个加难 → 失败与排错 → 边界与不适用场景**。
> 与本 Skill 既有规范的关系：`references/02` 的五模板决定文章骨架，本文件决定**证据怎么摆**。两者同时生效，不互相替代。

---

## 零、什么时候读本文件

`SKILL.md` 第 3 步判定为「实操分享」形态时，本文与 `references/02-article-structures.md` 一起读；判为评测形态时不必读，避免白读一整套。

一句话判据：**读者拿这篇文章，是想「做决定」，还是想「照着做」？**

## 一、判体裁与选结构（先判形态，再挑模板）

### 1.1 三问定形态

| 三问 | 都答「是」→ 评测骨架 | 出现「要做出东西」→ 实操分享 |
| :--- | :--- | :--- |
| 读者要的是「买不买 / 换不换 / 选哪个」吗？ | 是 | 否 |
| 核心证据是「同题对比 / 胜负总表」吗？ | 是 | 否（核心证据是**我做出来的那个交付物**） |
| 读者能照着复现出一件东西吗？ | 不必须 | 必须 |

### 1.2 形态与模板的映射（对应 `references/02` 五模板）

| 形态 | 用哪个模板 | 首选骨架 | 判断线索 |
| :--- | :--- | :--- | :--- |
| 从零装 / 跑 / 出片 / 上线 | 模板 4 · 从零做出来 | `classic-edit`（编号章节 + STEP 卡 + 深色代码块） | 材料里有一串可按顺序执行的步骤 |
| 手册 / 词典 / 参数表 / 模式清单 | 模板 5 · 手册词典 | `journal`（对照表承载信息），封面可配 `paper` | 材料主体是「名称 + 做什么 + 怎么用」的平铺条目 |
| 单点复刻 / 一次翻车后的修好过程 | 模板 4（缩短版） | `ticket` | 全篇围绕一个动作的一次成败 |
| 真跑横评 / 榜单选型 | 模板 1–3（评测骨架，不变） | `magazine-card` / `ticket` | 核心是「谁更强」的胜负总表 |

### 1.3 体裁判错的典型后果（比句式问题严重得多）

- 标题许的是**做出东西**，正文却是背景科普与行业必要性 —— 读者拿不走步骤。
- 标题许的是**结论**，正文却是从零安装 —— 读者拿不到站队。
- 手册型内容套上「五幕评测」外壳 —— 读者期待胜负，拿到的是词表。

**条文**：体裁判定必须在写提纲之前完成，一句话写在选题卡上；判定后骨架跟着形态走，不跟着「上一篇用了什么」走。

## 二、版本锚点行（可复现性的地基）

### 2.1 固定格式

在正文前 1/3 内出现一行，五个字段缺一不可：

> **工具及版本 / 模型名 / 硬件或云卡 / 额度或积分 / 操作日期**

示例形态（内容是自己的，格式固定）：

> ComfyUI v0.3.x / 本地推理模型（按官方发布名填写）/ 12GB 消费级显卡 / 平台赠送的试用点数 / 2026-11-xx

### 2.2 三条硬规则

1. **锚点必须是版本号、模型名、硬件规格、额度数字**，不能是「限时活动名」「首发福利」「现在免费」。活动会过期，版本号不会。
2. **模型名写死在最显眼的位置，就必须同时给出查询日期**。写在最易过期位置又不标日期，等于给读者埋雷。
3. **后续每一处「我这里是 X」都要与锚点行自洽**。正文说 8GB 能跑、锚点写 24GB 卡，属于自相矛盾，必须先改一致。

### 2.3 硬件写成判断轴，而非炫配

把硬件分档直接做成读者的分流器：什么档位能跑什么、什么分辨率该降、哪些模型只是「跑得动」而不是「能用」。读者拿这一张分档表，比拿一句「配置要求不高」有用一百倍。

## 三、可复制资产四件套（可复制的不是那句话，是「那段话 + 它能成立的前提」）

任何一段可复制内容（提示词、命令、配置、参数组）进正文，必须同时在场四样东西。缺一件就**标缺口**，不许当作完整资产交付。

| # | 要素 | 具体要求 | 缺了怎么办 |
| :--- | :--- | :--- | :--- |
| 1 | **原话** | 原样可粘贴，不转述、不压缩、不改写 | 只能转述时，明写「原话未取得」 |
| 2 | **上下文** | 在哪个工具/哪个版本/哪种账号/什么硬件上跑 | 明写「条件不完整，照抄需自测」 |
| 3 | **它换来的结果** | 输出文本、文件、目录树、截图、耗时数字之一 | 删掉「效果很好」这类宣称 |
| 4 | **失败边界** | 什么输入下它会崩、它不解决什么 | 至少补一句「本篇未覆盖的条件」 |

### 3.1 占位符必须解释

`[产品名]`、`[你的域名]` 这类方括号占位，必须紧跟一句替换说明：填什么、填错会怎样。留着不解释的占位符，读者大概率填错，然后以为是你的方法有问题。

### 3.2 严禁「转贴他人提示词当自测」

把他人文章里的提示词贴进自己的「可抄原件」区，却没说明自己没跑过 —— 这既是模仿，也是伪造实测。要么自己跑一遍，要么明写「该提示词转自公开分享，本篇未复现」。

### 3.3 命令与短指令

延续 `SKILL.md` 的清爽排版铁律：只留 1–4 行纯命令，不写 `【原件 X】` 标题头，不写 `#` 废话注释。

## 四、宣称—证据对照表（写结论前先填表）

### 4.1 作业稿里必做的一张两列表

| 我要宣称什么 | 哪张图 / 哪段日志 / 哪行数字能证 |
| :--- | :--- |
| （原句照抄自己要写的那句话） | （可指认的证据：文件名、日志行、截图位置、数字出处） |

### 4.2 三条判定

1. **右列为空** → 这句话要么删掉，要么改写成「作者称」「网传」。
2. **右列只有情绪**（「效果非常好」「明显更流畅」）→ 视为空，同样降级。
3. **右列与左列对不上** → 不许替作者圆场，把差异**原样标成疑点**写出来。差异本身是信息。

### 4.3 失败样本的展示价值

同一题里既有改成功的样本、也有没改好的样本，可信度远高于「四轮全成功、零失败」。失败现场原样贴出（接口返回空列表就是空列表，不配成功文案），比任何形容词都有说服力。

## 五、失败边界写法（症状 → 原因 → 一步补救）

### 5.1 与现行「不写踩坑」的边界澄清

`references/02` 里的「彻底不写踩了什么坑」，针对的是**评测文的叙事结构**——不许把评测文写成翻车日记。**实操分享必须给失败边界**，但要用「症状对照表 / 边界清单」的形态给，不是用讲故事的口吻倒苦水。

一句话区分：**评测文不写我的翻车过程；实操文必须写读者会撞上哪堵墙。**

### 5.2 三列表（缺列不算写完）

| 症状（屏幕上看到什么） | 原因 | 一步补救 |
| :--- | :--- | :--- |
| （照抄报错原文或现象原样，别转述） | （一句话点明根因） | （一个具体动作，能立刻做） |

硬规则：

1. **症状要可照抄**：写读者屏幕上真实出现的那行字或那个现象，不写「可能会出问题」。
2. **一个症状只配一个主要补救动作**。给三个并列选项等于没给。
3. **禁止空警示**：「注意版权」「注意安全」「小心封号」不算失败边界，它们没有症状、没有原因、没有动作。
4. **禁止情绪表演**：「我差点崩溃」不写症状和补救，属于无效篇幅。

### 5.3 时间对写法（推荐）

一次真实翻车可以写成一对数字：**第一次跑出的结果 → 修好之后的结果**，中间夹一句「改了什么」。读者拿的是因果，不是剧情。

## 六、范围声明（写到哪、不写什么、只到第几个）

### 6.1 三个必答

在开篇或目录后，用一到两句交代：

1. **覆盖到哪一步**：能装能跑 / 能出片 / 能上线 / 能交付给客户（选一个明确的终点）。
2. **不覆盖什么**：不谈成本 / 不谈合规 / 不做完整词典 / 不涉及团队协作（写清楚）。
3. **只到第几个**：手册型必须写明本篇写到第 N 个条目，下篇从第 N+1 个继续。

### 6.2 范围声明是可信度，不是免责套话

它的作用不是免责，而是**让读者不会拿着半截教程去指望完整结果**。写清边界的人，比写「一篇就够」的人更值得信任。

### 6.3 标题量词必须被正文兑现

标题里出现「万字」「最全」「一篇就够」「完整版」，正文必须有对应体量与覆盖度。兑现不了就改标题，不许靠加长铺垫凑数。

## 七、成本与额度写法（给公式，不给感觉）

### 7.1 三数可复算

成本必须能被读者用三个数自己算出来：

> **单价**（官网/平台价，带查询日期）× **用量**（几次调用 / 几秒 / 几 MB / 几条） × **报废率**（抽卡倍数，例如「平均 1.5 次成 1 条」）

给出这个算式和三个数，读者就能据此给自己报价。只写「一共花了几块」不可复算，因为它没交代用量和报废。

### 7.2 报告额度而不是报告贵

写「每次尝试消耗 X 点数，平台单价 Y 元/点数」，比写「有点贵」有用。「限时免费」「白嫖」「几乎不花钱」「一杯咖啡的钱」一律不构成成本信息。

### 7.3 与评测文的算账表分工

`references/02` 模板 1–3 里的《成本算账单》回答「值不值得买」；本节回答「我做到这个结果要花多少」。两者都需要查询日期，都不许用感觉代替单价。

## 八、他人素材三条线（可学 / 可短引 / 不可搬）

| 线 | 允许什么 | 边界 |
| :--- | :--- | :--- |
| **可学** | 结构、判据、顺序、边界表、决策树、信息组织方式 | 学完必须用自己跑的数据与场景重写内容 |
| **可短引** | 不超过必要一句的原话 | 必须带来源 url，且必须有自己的解读；一句能说清就不用两句 |
| **不可搬** | 整段原文、提示词全文、别人的口吻与招牌句式 | 同义词改写也算搬；换说法不产生原创 |

补充三条：

1. **二手材料只能当方法样本**。解读他人公开方法时，句式落在「他公开的方法是……」「这套思路可以这样迁移到……」；不得写成「我试了，确实……」。
2. **对方数字要带口径**。引用他人成绩数字时，必须交代这个数字是什么口径（本帖曝光？粉丝数？官方公布？），口径缺失就只能当「作者称」的传闻处理，不得当作自己的结论背书。
3. **原文链接未打开或未取得时，明写「原文链接未取得」**，不许装成读过了。

## 九、视频与未取得资产的写法（诚实优先于丰满）

### 9.1 视频：没看就写「视频效果未验证」

- **固定句式**：「成片效果在视频里，视频效果未验证。」
- **硬规则**：没看视频，正文**不得出现任何对其画面的描述** —— 不能写「口型很准」「运镜丝滑」「衔接自然」「动作稳定」。
- **静帧不能代替视频**：静帧不含时序信息，看一张图推不出「衔接自然」。由静帧得出的结论一律降级为「截帧显示……」。
- **他人视频同理**：引用他人的成片视频，只能写「证据在这段视频里，本篇未逐帧核验」。

### 9.2 未取得的资产（资料包 / 课件 / 开箱库 / 源码包）

- **固定写法**：「该资产在未取得的包里，本篇不展开。」
- **硬规则**：未取得 ≠ 已读。包内步骤**不得**写成已完成步骤，包内参数**不得**写成自己核过的参数。
- 若必须提到，只写「据作者描述，包内包含……」，并明确标注这是转述。

### 9.3 设计稿与成品的关系

设计稿、示意图、界面概念图**不得**放在「成果先展示」位置，只能放在「我计划长这样」。第一屏的交付物必须是**可核的成品**——图里能看见时间、文件名、尺寸、状态之一。

### 9.4 曝光与阅读必须分列

引用他人帖子的传播成绩时，唯一合法口径是**本帖 API 曝光数**（平台 `impression_count` 一类字段）。不得写成阅读量、打开率、完读率，也不得由点赞/收藏反推阅读量。要说「正文被读过」，唯一合法依据是**自己完整通读了对方正文**，且这句话说的是「我读了」，不是「有多少人读了」。

## 十、交付前自检 10 问（人工必过，脚本不替代）

发布前逐条打勾，任一条为「否」就回去改，不许带着缺陷进草稿箱。

| # | 自检问题 | 不合格表现 | 对应章节 |
| ---: | :--- | :--- | :--- |
| 1 | **体裁判断对了吗？** 标题承诺的是「做决定」还是「做出东西」，正文是同一种吗？ | 标题讲战绩、正文是入门教程 | §1 |
| 2 | **第一屏有可核交付物吗？** 图里能看见时间/文件名/尺寸/状态之一吗？ | 交付物在第四屏；用设计稿冒充成品 | §9.3 |
| 3 | **每段可复制资产四件齐吗？** 原话、上下文、结果、失败边界？ | 只贴提示词不贴回显；占位符不解释 | §3 |
| 4 | **版本锚点行在正文前 1/3 吗？** 且五字段齐全、不是活动名？ | 用「限时免费」当锚点；模型名无查询日期 | §2 |
| 5 | **宣称—证据表右列有没有空格？** 空的那句改了吗？ | 右列为空仍保留原句，把「作者称」写成「我测了」 | §4 |
| 6 | **失败边界是不是三列表？** 症状可照抄、原因一句话、补救一个动作？ | 「注意版权」「注意安全」式空警示 | §5 |
| 7 | **范围声明写了吗？** 覆盖到哪、不覆盖什么、只到第几个？ | 标题「最全/万字/一篇就够」，正文撑不住 | §6 |
| 8 | **成本可复算吗？** 单价（带查询日期）× 用量 × 报废率？ | 「一杯咖啡钱」「几乎免费」 | §7 |
| 9 | **他人素材守住三条线了吗？** 没有整段搬运、没有同义词洗稿、短引都带 url？ | 转贴他人提示词却说自测过；拿对方数字给自己背书 | §8 |
| 10 | **视频与未取得资产写诚实了吗？** 有「视频效果未验证」吗？ | 看静帧写「口型很准」；把未取得的包当已读 | §9 |

### 10.1 红线条（任一触发即打回，不商量）

- **捏造 I/O**：正文写出某个终端输出/返回结果，而真跑回执里没有这行 —— 一票否决。
- **把曝光当阅读**：出现「阅读量」「打开率」「完读率」并挂数字。
- **把没看的视频写成已验证**。
- **整段搬运他人正文且无来源 url**。
- **覆盖或改写封面引擎受保护文件**（目录级保护，任何补丁都不许碰）。

### 10.2 一条反向红线（防误伤，必须记住）

**允许批评第三方中转、公益站、邀请码生态，也必须允许写它们的风险。** 判定标准是「有没有宣称与证据落差」，不是「这个主题能不能写」。

- ✅ 合规写法（不许拦）：「该路径依赖第三方交易，价格与可用性本篇未核，不构成推荐。」「这篇样本自称免费公益，但截图里是余额看板与按量计价页，与宣称对不上，因此不作为实操范本。」
- ❌ 违规写法（要拦）：「第一步，去某交易页买邀请码，第二步填进配置里白嫖额度。」——把不可核验的第三方交易写成推荐步骤，且无风险提示。

条文里永远不许出现「某类服务一律不写」的规则。规则管的是「推荐无风险提示」，不是「主题黑名单」。
